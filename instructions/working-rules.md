# 작업 규칙 (worknotes-kit)

- 코딩 전에 먼저 정리한다: ①명시된 요구 ②미확인 정보 ③가정 ④완료 기준. 미확인은 사실처럼 쓰지 말고 확인할 질문으로 남긴다.
- 업무 기준이 모호하면 추측으로 확정하지 않는다. 담당자에게 물을 질문을 만들고, 답을 받기 전에는 "확인 전 가정"이라고 코드 주석과 문서에 표시한 잠정 구현을 쓴다. 요구된 인터페이스와 필수 필드는 유효한 값으로 채우고 null·빈 값으로 비우지 않는다.
- 요구에 없는 기능·추상화·의존성·과한 방어 코드는 추가하지 않는다. 가장 작은 변경으로 시작한다.
- 원본 데이터 파일은 수정하지 않는다. 변환 결과는 별도 파일이나 출력으로 만든다.
- 중요한 선택은 이유와 대안을 한 줄로 기록한다.
- 완료라고 말하기 전에 실제로 실행해 확인한다. 실행하지 않았거나 실패한 것은 "미검증"·"실패"라고 쓰고 통과라고 쓰지 않는다. 테스트 통과와 요구사항 충족은 다르다.
- 오류가 나면 추측으로 계속 고치지 않는다. 재현 → 원인 가설과 근거 → 최소 수정 → 같은 조건으로 재검증 순서로 진행하고, 3번 실패하면 접근을 다시 검토한다.
- 키·토큰 같은 비밀값을 코드·로그·문서에 쓰지 않고, 문제·데이터·결과물을 외부로 보내지 않는다.
- 문서에는 실제로 한 일과 확인한 결과만 쓴다. 과제가 요구하는 제출 문서가 있으면 그 문서에 쓰고, `TASK.md` 같은 별도 문서는 과제가 클 때만 만든다. 작은 요청에는 만들지 않는다.

## 단계별 절차 파일
자동으로 적용되지 않으면 해당 파일을 읽고 그 절차대로 진행한다. (키트를 `kit/`에 가져왔다고 가정)

| 단계 | 파일 |
|---|---|
| 요구 정리·담당자 질문 | `kit/skills/work-intake/SKILL.md` |
| 오류 해결 | `kit/skills/debug-rootcause/SKILL.md` |
| 완료 전 검증 | `kit/skills/verify-evidence/SKILL.md` |
| 정리·설명 대비 | `kit/skills/handoff-explain/SKILL.md` |
