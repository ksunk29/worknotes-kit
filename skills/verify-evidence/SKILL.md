# 완료 주장 전에 근거 확인

1. 요구사항 목록(`TASK.md`)을 요구 하나씩 나눈다.
2. 요구마다 **무엇으로 확인할지**(실행 명령, 입력, 기대 결과)를 먼저 정한다.
3. 실제로 실행하고 **출력과 종료 코드를 읽는다.** 명령이 실패했거나 출력이 기대와 다르면 통과가 아니다.
4. `VERIFY.md`에 요구마다 아래를 적는다.
   - 확인한 것: 명령, 결과, 시각 순서가 아닌 요구 기준으로
   - 확인하지 못한 것: 이유와 함께 "미검증"
   - 실패한 것: 현상과 남은 문제
5. 구분해서 말한다. 테스트 통과, 실행 성공, 요구사항 충족은 서로 다른 주장이다.
6. 화면이 있는 결과물은 직접 열어 입력·버튼·빈 상태·오류 상태를 눈으로 확인한다. 코드에 있는 기능이 화면이나 안내에 빠져 있지 않은지도 본다.

산출물: 요구별 확인 표. 과제가 요구하는 문서가 있으면 그 안에, 없고 과제가 클 때만 `VERIFY.md`로 쓴다.

하지 않을 것: 실행하지 않은 검증을 통과라고 쓰기, 출력이 없다는 이유로 성공이라 판단하기, 서버처럼 끝나지 않는 명령을 검증 명령으로 쓰기.
